# 三体文明游戏设计文档

## 一、界面与交互体验设计

* **数据告警效果**：当"表面温度"过热过低，或"社会安定度"低于一定阈值时，相关字体颜色不仅会变红，还要加入轻微的闪烁（Flicker）效果与全局的红色警报滤镜。
* **信息高亮提示（Tooltip）**：鼠标悬浮在某个资源或参数上时，浮现出半透明说明框，解释该数据的变化来源。
* 未来会进一步在主界面加深粒子星空背景的随机变化，以应对环境状态改变时的直观情绪传达。
* **区域浏览界面**：2D Mercator投影风格的行星展开图，12×6网格热力图显示温度/辐射/光照，点击区域查看详细数据和建筑列表。
* **区域分栏**：热力图与详情栏约按 2:1 分配宽度，两侧内容不得重叠，地图绘制必须裁剪在左侧面板内。
* **全局返回规则**：`Esc` 在游戏子界面返回上一界面；在主游戏界面打开暂停菜单；在暂停菜单恢复游戏。
* **全局暂停规则**：空格在主游戏界面以及科技树、政策、区域/建筑、星图等游戏子界面统一切换暂停/继续；子界面必须给出当前暂停状态反馈。
* **批量人口分配**：生育人口与建筑工人必须提供 `±1`、`±10`、最大/填满和清空操作；批量值超过闲置人口、岗位容量或当前分配量时自动取可用上限。
* **时间倍率**：主界面使用四段滑条选择 `1x/2x/3x/5x`，并在滑条旁持续显示当前倍率。
* **项目内存档**：开发阶段存档固定在 `res://saves/`；创建宇宙时必须生成初始存档，暂停菜单支持命名手动存档，加载界面按宇宙展示全部存档。
* **统一加载界面**：主菜单“加载存档”与暂停菜单“加载游戏”必须打开同一套可选择存档列表；列表直接展示存档名、宇宙、游戏天数和保存时间，并支持加载与删除。
* **开发期可见存储**：完成开发前，设置与存档统一放在 `res://settings.json`、`res://saves/`，不使用 `user://`；正式发布时再设计迁移策略。
* **分辨率适配**：界面以 1920×1080 为设计基准，通过 Canvas 缩放、锚点、容器和统一安全边距适配 1080p、2.5K 与更高常规分辨率；顶部导航、底部提示、地图与详情栏不得重叠或裁出屏幕。
* **提示可读性**：暂停菜单的保存结果与各界面底部操作提示使用独立面板、足够字号和高对比色，不得依赖低对比的小字。
* **开发者模式**：在设置中显式启用。模式开启后可绕过只用于界面访问的科技门槛，并从主界面的开发者工具修改当前测试局的人口、资源、科研点或解锁科技；工具架构需为时间、事件和环境调试预留扩展位置。

### 主游戏页面：区域地表观测（规划，尚未实现）

主游戏页面不再以三块等权数据面板作为视觉主体。资源、文明和环境数据仍必须可见，但收纳到屏幕底边、左右边缘或可折叠 HUD；画面中央用于展示玩家当前选择的行星区域。

#### 画面构成

- 画面上半部约占 55%~65%，表现从当前区域地表仰望的真实天空；下半部约占 35%~45%，表现该区域的地面和地平线。
- 天空必须复用 3D 星图的恒星材质、日冕、深空环境与天体实时位置，不允许维护一套与模拟状态脱节的装饰天空。
- 观察点取所选区域中心经纬度，并叠加行星当前自转角。区域球面法线作为当地天顶，东西/南北切线构成地平坐标系。
- 每颗恒星相对行星的真实方向需转换到当地地平坐标；低于地平线的天体被地面遮挡，位于地平线以上的天体按距离、半径和颜色显示正确的方位、相对角直径与光照影响。
- 白昼、黄昏和黑夜由区域实时光照自然产生；极端辐射、温度和多恒星同现应通过天空颜色、曝光和告警层表达，但不能伪造模拟结果。
- 第一阶段的地面只需按地形类型生成可辨识的空白地表、地平线、雾和基础光照，不生成装饰性假建筑。
- 后续建筑系统接入后，地面视图按区域建筑、施工进度、损毁状态和人口活动动态实例化场景；当前空白地面是明确的扩展插槽。

#### 区域选择与 HUD

- 玩家可从紧凑区域选择器、缩略热力图或“区域/建筑”界面随时更换主页面观察区域。
- 更换“观察区域”只改变镜头和 HUD 数据，不等同于迁都、移动人口或改变当前建造目标；这些游戏行为必须使用各自的明确操作。
- 当前区域名称/编号、地形、温度、辐射、光照、人口和建筑摘要沿边缘显示；全局人口、核心库存、科研/知识状态、时间、倍率和暂停状态集中到底栏。
- 告警可以临时扩展，但常态 HUD 不得遮挡天空主体、地平线和未来建筑展示区。
- 当前观察区域写入存档；读取旧存档时默认使用首都区，首都区尚未实现时回退到区域 `0`。

#### 验收标准

1. 选择两个经纬度不同的区域时，同一时刻看到的恒星高度和方位不同。
2. 区域进入背光面后恒星落到地平线以下，地表和天空同步进入夜间表现。
3. 星图和主页面地表天空对同一时刻的天体位置、颜色和碰撞状态保持一致。
4. 不打开额外面板也能看到生存所需的关键数据，但中央画面不再被三块数据面板占满。
5. 地面节点能够在不重写天空渲染和 HUD 的情况下接入区域建筑可视化。

## 二、行星区域系统

### 1. 球体分区
行星被划分为 **72个区域**（12经度带 × 6纬度带），每个区域覆盖30°经度 × 30°纬度的球面。

- 极地区域面积小（cos权重），赤道区域面积最大
- 每个区域有随机地形类型（平原、高原、山地、峡谷、盆地、丘陵）
- 地形决定区域的资源禀赋：铁矿、铜矿、稀有矿、肥沃度、藻类密度
- 区域温度影响区域内工人的工作效率（过高过低都会导致效率下降甚至停工）
- 区域面积权重影响全球平均值的计算

### 2. 行星自转
- 自转速度：15°/游戏天
- 自转角度影响每个区域的法线方向
- 面朝恒星的区域接受直射辐射，背面区域仅有5%散射辐射
- 温度具有热惯性，不会瞬变

### 3. 逐区环境计算
每帧对每个区域：
1. 计算区域法线 `normal = sphere_normal(lat, lon + rotation_angle)`
2. 对每颗恒星计算方向和距离
3. 光照 = `max(0, dot(normal, star_dir)) × mass × 10 / (dist² + 100)`
4. 辐射 = 类似计算，衰减更快（dist^2.5）
5. 温度 = `-273.15 + Σ(光照贡献 × 50)`

### 4. 建筑与区域
- 建筑有所在区域ID
- 建筑有耐久度、热/冷/辐射抗性
- 区域温度/辐射超过抗性阈值时，建筑受损
- 耐久度归零时建筑损毁
- 建筑的产出由分配的工人数量、工种的基础产出、电力负载平衡、科技自动化倍率以及温度效率综合决定
- 科技可强化建筑抗性（防辐射装甲、高强度合金等）

## 三、知识与科技演化系统（核心玩法规划，尚未实现）

> 当前运行版本的“5 层 19 节点 + 基础/应用/理论科研点”仅是验证研究、建筑和存档链路的原型，不再作为最终科技设计。后续迁移必须保留旧存档兼容，但玩家的新开局将从原始文明开始。

### 1. 设计目标

- 文明开局只有语言雏形、口耳相传、简单计数、火与石木工具等原始能力，不会预先知道“计算机”“核聚变”或“三体混沌预测”等具体科技名称。
- 科技不是商店列表，而是“观察现象 → 获得模糊线索 → 形成可验证理解 → 组织研究 → 掌握理论 → 工程化应用”的连续过程。
- 科技树是有向分岔图。只有理解某个节点后，才逐步显露它能引出的相邻方向；尚无认知基础的远端科技完全隐藏。
- 知识能够跨代累积，也会因人口死亡、教师断层、载体损毁、灾难和长期停用而丢失。建设记录、教育和研究机构既是加速器，也是文明记忆的保险。
- 上一代文明遗迹、器物与记录能够提供跨时代线索，但不能无条件直接解锁超出现有实验、材料和制造能力的科技。

### 2. 科技节点生命周期

每个科技节点至少具有以下状态，状态变化必须由知识系统统一管理：

| 状态 | 玩家可见内容 | 含义 |
|---|---|---|
| `HIDDEN` 未知 | 不显示节点 | 文明尚无相关概念，不能研究 |
| `RUMOR` 模糊方向 | 只显示领域轮廓、未知效果和线索来源 | 观察或事件暗示“这里可能存在规律” |
| `INSIGHT` 已理解问题 | 显示现象、待验证假说和前置条件 | 文明知道要研究什么，但证据/工具可能不足 |
| `RESEARCHABLE` 可研究 | 显示具体项目、成本、实验和设施需求 | 已满足开始系统研究的条件 |
| `RESEARCHING` 研究中 | 显示进度、证据缺口和风险 | 人员、时间、材料与观测数据持续投入 |
| `MASTERED` 理论掌握 | 显示理论效果和后续分岔 | 理论已建立，但不代表能立即制造设备 |
| `APPLIED` 工程化 | 显示建筑、工艺、政策或自动化能力 | 已完成样机、工艺验证和规模化应用 |
| `DEGRADED` 知识衰退 | 显示缺失环节和恢复路径 | 文献/传承不足，部分设计、维护或研究能力失效 |

状态不是简单单向布尔值：`MASTERED/APPLIED` 节点可能因知识衰退进入 `DEGRADED`，恢复后回到原状态。已经存在的建筑不会凭空消失，但文明可能暂时无法新建、升级或完整维修它。

### 3. 知识发现来源

- **自然观察**：昼夜、季节、恒星运动、坠落、燃烧、腐败、疾病、矿石熔融、电现象等长期数据积累。
- **主动实验**：玩家安排测量、对照、解剖、冶炼、材料试验、轨道观测或原型制造，消耗人员、材料、能源和时间。
- **生产经验**：农业、采矿、建筑和手工业在实际运行中产生工艺经验，可能触发改良线索。
- **随机事件**：天象、灾难、异常材料、关键人物、实验事故、思想争论等事件可授予某个节点的 `RUMOR/INSIGHT`、证据片段或研究修正，事件系统不得直接修改 UI 状态。
- **遗迹发掘**：勘探上一代文明遗址，取得器物、残缺记录、数据载体和设施。产物分为“可直接使用的遗物”“可解读的知识片段”“当前无法理解的沉睡档案”。
- **跨领域联想**：数学、测量、材料和能量等基础节点达到条件后，可自动显露多个领域之间的新分岔。

随机事件与考古系统只调用知识系统公开入口，例如“添加线索、添加证据、提高熟悉度、揭示候选节点”；具体能否进入 `RESEARCHABLE` 由节点前置、文明能力和证据共同判定，为未来扩展预留空间。

### 4. 知识传承、载体与丢失

每个知识领域维护“活态传承、记录完整度、实践熟练度”三类值：

- **活态传承**来自掌握者、教师、学徒和持续实践；人口代际更替时按教育覆盖率传给下一代。
- **记录完整度**来自岩刻、文字、档案馆、印刷、磁/光存储等载体；载体越先进，复制速度和抗灾能力越高，但依赖对应材料、能源和维护。
- **实践熟练度**来自相关建筑和工艺持续运行；长期停产会先丢失诀窍，再影响理论之外的工程化能力。
- 知识衰减按“代”结算并受灾难即时打击，不应每帧随机扣除。教师数量、记录副本、地域分散、机构耐久和文明人口决定保留率。
- 某节点低于维持阈值时先失去研究加成和高级维修能力，再进入 `DEGRADED`；核心概念只有在活态传承、记录和实践同时断绝时才完全退回线索状态。
- 口述、文字、学校、档案馆、大学、自动备份构成逐级增强的知识基础设施路线，而不是抽象的永久 Buff。

### 5. 知识政策树：教育、载体与避难取舍

知识传承不由单一数值自动完成，而是由制度、岗位、载体和灾难预案共同决定。知识政策树与科技图分离：科技图描述文明“知道什么”，知识政策树描述文明“如何教、如何记、危机时保存什么”。政策节点仍受时代能力约束，尚未发明文字的文明不能选择纸质档案，尚未建立学校的文明也不能直接实行普及教育。

#### 5.1 总体重视度与细分优先级

- 玩家可设置 `0~100` 的“知识重视度”，用于日常自动分配教育、抄写、档案维护和灾难保护资源。它只是默认分配倾向，不提供无成本研究加成，也不能突破物理容量。
- 玩家可进一步设置四类传承载体优先级：**教师/专家、学徒/学生、记录副本、实物样机/关键工具**。教师本身也是需要食物、床位和生命保障的人口，不能在“人口”和“知识”中重复计算。
- 玩家可按生存医学、农业、材料、数学测量、自然规律、天文航天等知识领域设置保存权重，并可给少数关键节点设置手动保底。
- 自动分配只在玩家未逐项指定时生效；界面始终可以显示当前方案的床位/库位占用、已纳入与未纳入对象，但“预计获救、伤亡和知识衰退”属于需要科技与观测数据解锁的推断信息。可能造成不可逆后果的方案需要明确确认，即使文明暂时无法准确量化后果。

#### 5.2 教书与活态传承

- 教师、讲述者、师傅和学徒导师是实际岗位。任教会减少当期可用于采集、生产、建筑和研究的人力；学生学习也会暂时减少劳动时间。
- 传递效率由教师掌握度、师生比、教学时间、共同语言/识字率、教材、教学场所和学生基础共同决定。没有掌握该知识的教师不能只靠政策生成知识。
- 口述适合保存核心经验但容量和精度有限；师徒制适合传递隐性工艺但覆盖面小；学校提高广度和代际稳定性；大学和专业训练提高深度但消耗更多成年劳动力。
- 只读文献不能完整恢复需要手感、调试和现场判断的工艺。此类知识还需教师示范、学徒实践或可运行样机；长期没有实践会先损失工艺熟练度。
- 危机前可开设“抢救式教学”，在较短时间把生存要点、基础读写或某项关键工艺传给更多人，但只能形成较浅层的传承，并带来生产停顿、疲劳和教学质量下降。

#### 5.3 载体、复制与分布式保存

- 传承路线随能力逐步出现：集体讲述/记忆者 → 师徒制 → 符号记录与抄写员 → 学校与课程 → 纸张、印刷、图书馆与异地档案 → 数字化、离线副本与自动校验。
- 纸质时代的保存需要纸张、墨、抄写/印刷人力、干燥空间、防火、防水、防虫和目录维护；“写在纸上”不等于永久保存。
- 多份记录只有放在相互独立的区域或避难设施中才形成抗灾冗余。大量副本会消耗材料、运输、维护和可用空间。
- 实物样机、量具、模具、种子和关键工具可保存文献无法表达的实践信息，但通常比纸张更重、更占空间，也需要防锈、供电或定期维护。

#### 5.4 地下避难所的真实容量竞争

避难设施至少分别计算**可用体积、床位/生命保障、食物与水、干燥档案容量、重型物品容量、能源与环境控制**。不同保存对象占用不同约束，不能用一个虚构的“知识点容量”替代：

- 普通人口、教师、专家和学徒都占用床位、生命保障与食物；教师/专家的额外价值来自其携带的活态知识，而不是少占一个人口名额。
- 纸质档案主要占用干燥体积、货架、防火与环境控制；在生命保障不足但尚有干燥库位时，保存档案不必等价挤走一个人。
- 样机、模具和关键工具占用体积、承重、搬运与维护能力；部分设备还持续耗电。
- 当任何关键容量不足时，系统按玩家的避难方案进行取舍：优先救援普通人口、优先保护教师/专家、保留学徒梯队、转移关键档案、保存样机，或采取均衡策略。极端“知识优先”可能牺牲更多人口，但不能凭空保存所有对象。确认界面必须完整显示玩家主动留下了哪些人和物；灾害造成的实际伤亡与损失则只能按文明已有预测能力显示。
- 灾难结束后还需选择恢复次序，例如先恢复生命保障和农业、先重建学校与抄写、先修复样机或先整理档案；保存下来的材料只有被解读、教学和实践后才重新转化为可用能力。

##### 危机结果预览也是科技能力

避难方案的**装载事实**与灾害的**结果预测**必须分开。玩家通常可以知道某避难所还剩多少已测床位、生命保障和档案空间，也可以知道哪些人或档案未被纳入方案；但如果文明不知道恒星将从哪里经过、何时接近、会造成多少热量和辐射，就不能获得准确伤亡数字或知识损毁概率。

“伤亡评估”不是开局自带 UI 功能，而是由天文学、测量、统计、灾害模型和工程数据共同形成的应用能力，并按以下层级逐步显露：

| 预测层级 | 所需认知与设施 | 玩家能看到的内容 |
|---|---|---|
| 无预测 | 尚无有效轨道与灾害模型 | 已装载/未装载人数和物资；伤亡、受灾区域和知识损失显示“未知” |
| 经验预警 | 长期天象记录、历法、灾害记忆 | “风险正在升高”等定性判断和很宽的时间窗口，不显示伪精确人数 |
| 区域风险 | 望远镜、精密计时/测角、基础轨道理论、区域环境记录 | 可能受灾区域、风险等级和宽区间伤亡/损失，明确标注低置信度 |
| 定量评估 | 多体数值方法、统计误差、校准观测站、人口与建筑模型 | 多套轨道情景、到达时间范围、伤亡区间、知识退化风险和置信度 |
| 高精度预报 | 卫星网络、持续遥测、计算设施、自动拟合与校准 | 更窄的概率区间和方案对比，但混沌系统中仍不承诺单一精确结果 |

科技图通过 `hazard_warning`、`regional_hazard_projection`、`casualty_estimation`、`knowledge_loss_projection` 等能力标签逐级开放显示层级；解锁理论节点只代表会做这种分析，实际精度还取决于观测时间跨度、仪器质量、卫星覆盖、计算能力和区域人口/建筑数据完整度。

难度规则提供的“第几年开始混沌”只是一条玩家可见的玩法保证，不等于文明掌握了届时的真实轨道与灾害后果。界面必须把规则倒计时与文明预测分栏显示，禁止用规则层的隐藏模拟结果填充伤亡预览。

当信息不足时，方案比较只显示确定的容量与暴露对象，以及“如果该区域受灾则可能失去哪些知识”的条件风险。反复切换方案不能泄露真实未观测轨道、灾害强度或随机结果；灾害结算仍使用真实结果，预测偏差本身也是玩法的一部分。

#### 5.5 政策树分支

知识政策树采用“制度节点 + 可调权重 + 限时计划”，而不是把所有选择做成互斥按钮。建议分为四条可交叉的分支：

1. **教育与教学**：指定记忆者、师徒制、基础读写、固定课程、普及教育、专业教育、教师培养、危机速成课。
2. **记录与复制**：口述校对、专职抄写、统一术语、印刷、公共图书馆、异地副本、档案校验、离线数字备份。
3. **危机保存**：避难名册、教师/专家保护、学徒梯队、档案预打包、样机转移、分散避难、生命优先/均衡/知识优先应急姿态。
4. **灾后恢复与再发现**：幸存者普查、知识缺口审计、档案解读、师资恢复、工艺复现、遗迹与旧档案再发掘。

每个节点须显示解锁条件、教师/学生/维护岗位、材料、空间、能源、实施时间、预期保留率和机会成本。制度可以改善传递条件，但最终保留结果仍由实际教师、学生、载体、设施和灾害强度计算。

### 6. 科技树领域与早期演化

科技图不预设给玩家完整答案，但内部需要按领域组织，以便生成合理分岔：

1. **生存与社会记忆**：语言 → 计数 → 符号/文字 → 教育 → 档案与知识机构。
2. **工具与材料**：石木加工 → 火与陶器 → 冶炼观察 → 金属工艺 → 材料学与精密制造。
3. **生命与环境**：采集/驯化 → 农业实验 → 卫生与医学 → 生态学与生命保障。
4. **数学与测量**：长度/时间/角度 → 几何与代数 → 误差理论 → 数值计算与计算机。
5. **自然规律**：运动与力、热、光、声、电磁、物质变化分别由现象和实验逐步形成物理/化学体系。
6. **天文与航天**：肉眼天象 → 历法 → 光学观测 → 引力/轨道理论 → 火箭、卫星、遥测 → 多体观测与预测。
7. **工程与能源**：机械、结构、电力、自动控制、裂变/聚变等必须同时依赖理论、材料、制造、基础设施和安全验证。

早期 UI 只显示少量“观察天空”“保存经验”“改进工具”“理解火焰”等模糊方向。完成入门理解后才显示具体的计时、几何、陶器、冶炼等节点；远端节点不能通过缩放提前窥见名称和效果。

### 7. 研究资源与工程化

- 当前三种科研点在迁移期可保留为研究机构的“工作吞吐量”，但不能继续作为点击节点后自动解锁一切的唯一货币。
- 每个研究项目可要求领域知识、观察数据、实验样本、研究人员、设施、能源、材料和连续时间。
- `MASTERED` 只证明文明理解规律；解锁建筑或设备还需独立的工程化项目，包括样机、测试、可靠性、生产工艺和操作培训。
- 失败实验可以产生部分证据、事故或错误理论，不应简单清空所有进度。关键发现允许随机事件介入，但概率必须受实验质量和已有知识影响。
- 科技效果通过明确能力标签提供给建筑、观测、生产与 UI，禁止各系统依赖节点中文名称判断功能。

### 8. 科技树 UI

- 使用真正的树状/图状分岔布局，父节点理解后才绘制其直接子分支；跨领域依赖以较弱连线表示。
- `HIDDEN` 不占可见画布；`RUMOR` 使用模糊轮廓和方向描述；`INSIGHT` 展示问题与缺失证据；其余状态逐步增加精确信息。
- 节点详情分别显示“我们观察到了什么、当前假说、还缺什么、如何验证、理论收益、工程化路径、传承风险”。
- 提供领域筛选、搜索已知知识、传承风险视图和遗迹知识库；搜索不能泄露未知节点。
- 玩家可追踪多个线索，但同一机构的研究槽、实验设备和人员有限。
- 提供独立的知识政策页，并在科技节点上叠加“教师覆盖、记录副本、实践维持、危机保留率”风险；从风险项可跳转到对应政策、教学岗位或避难方案。

### 9. 存档与兼容

- 存档需保存每个节点的认知状态、线索/证据、研究进度、理论掌握、工程化进度、传承值、记录副本和衰退状态。
- 随机事件与遗迹发现必须保存来源 ID，防止重复领取一次性知识。
- 保存知识重视度、载体/领域权重、已采用制度、教师和学生分配、课程、档案副本位置、避难保存方案、限时教学计划及政策历史。
- 旧版 19 节点原型存档加载时通过迁移表转换为相应领域的已掌握/已工程化节点，并补充最低必要的基础知识链；不得静默丢失玩家已建造设施的能力。
- 该系统必须支持后续增加节点和事件，不以枚举序号作为稳定存档键，统一使用不可变字符串 ID 与数据版本号。

### 2. 人力分配与资源机制
- **人口驱动模型**：所有的生产活动都需要分配人口到对应岗位（铁矿工、铜矿工、电厂操作员、科学家等）。
- **细分资源**：
  - 矿物类：铁（基础材料）、铜（电气材料）、稀有矿物（高级科技）
  - 能源类：藻类燃料（初级）、化石燃料（中级）
  - 二次能源：电力（kW，建筑维持需要耗电，电力不足全境停电减产）
  - 维生：食物（不足将导致人口饿死）
- 玩家需要在“人口管理”界面动态分配空闲人口。建筑提供的“岗位上限”决定了最多能分配多少工人，而实际产出受岗位填满度影响。

### 3. 文明政策系统（通过主界面“政策”按钮）
- **全民脱水**：应对极端环境，资源消耗-80%，产出-90%
- **浸泡复苏**：恢复正常状态
- **大生育计划**：消耗500食物，人口增长+200%
- **配给制**：食物消耗-50%，效率和稳定性下降
- **工业强心剂**：产出+150%，健康和稳定性大幅下降

当前五项政策是运行版本中的扁平原型。后续政策界面扩展为政策树，其中知识分支按“教育与教学、记录与复制、危机保存、灾后恢复”组织；其详细规则以第三章第 5 节为准。政策树负责制度和资源优先级，科技图负责认知与能力，两者不得合并成同一组可购买节点。

## 五、星图与渐进式探索
* **初期盲区**：游戏开始时，星图系统被锁定。
* **视野解锁**：原始文明先通过肉眼天象和计时积累线索；理解光学、精密制造与系统观测后才逐级解锁简易望远镜、观测站和完整星图。
* **逐步预测**：几何、力学与轨道理论只提供理想二体预测；真实多体预测还需要持续观测数据、计算能力和卫星/遥测基础设施。
* **行星区域可视化**：星图中行星显示经纬网格线，随自转实时旋转。
* **星图空间质感**：背景保持深空层次；恒星具有动态表面与日冕并作为实际光源照亮行星；行星具有可辨识的海陆、云层、明暗面和大气边缘，经纬网不得遮盖地表细节。
* **行星锁定视角**：可锁定行星进行环绕观察，近距离观察区域分布。
* **碰撞终局**：任意两天体中心距离小于双方半径之和时立即暂停模拟并判定文明毁灭；星图显示游戏结束层并提供重新开始入口。

## 六、发电厂种类与能源体系

### 1. 设计目标
发电厂要有明确的类型区分（火电、核电、可再生能源等），不同发电厂各有优劣，玩家需要根据区域条件和科技进度选择合适的电力来源。

### 2. 发电厂类型（按科技层级递进）

| 层级 | 发电厂 | 燃料/条件 | 单工人出力 | 特点 |
|------|--------|----------|-----------|------|
| T0 | 藻类燃烧发电站 | 消耗藻类燃料 | 5kW | 入门电来源，效率低，污染低 |
| T1 | 生物质发电站 | 消耗食物/藻类 | 8kW | 比藻电高效，但消耗食物 |
| T2 | 火力发电站(煤) | 消耗化石燃料 | 15kW | 稳定大功率，高污染，受区域辐射影响小 |
| T2 | 火力发电站(油/气) | 消耗化石燃料 | 20kW | 比煤电更高效，污染中等 |
| T2 | 地热发电站 | 区域地形=火山/裂谷 | 25kW | 零燃料消耗，但受限于特定地形区域 |
| T3 | 太阳能阵列 | 区域光照强度 | 0~30kW | 零燃料，出力随光照波动，需储能配合 |
| T3 | 风力发电场 | 区域大气条件 | 0~20kW | 零燃料，出力不稳定，需储能配合 |
| T3 | 核裂变发电站 | 消耗稀有矿物(铀) | 50kW | 极高功率，需要辐射屏蔽配套，事故风险 |
| T4 | 核聚变发电站 | 消耗稀有矿物(氘/氦3) | 200kW | 终极能源，零污染，极高建设成本 |

### 3. 火电细分
火电不再是一个笼统的概念，区分为：
- **燃煤电站**：最基础的火电形式，污染最高，但建设成本低
- **燃油/燃气电站**：需要更高级的化石燃料精炼技术，效率更高，污染中等
- 未来可扩展：联合循环电站（T4，燃气+蒸汽联合循环，效率极高）

### 4. 发电厂差异化维度
每种发电厂在以下维度上有不同的数值：
- **燃料类型与消耗率**：零燃料(可再生) vs 消耗燃料
- **出力大小**：kW/工人
- **出力稳定性**：恒定 vs 受环境波动(光照/风力)
- **污染/环境影响**：影响区域宜居度和人口健康
- **建设与维护成本**：资源消耗 + 电力自耗
- **科技前置**：不同层级解锁
- **地形/区域限制**：部分发电厂只能在特定区域高效运作

### 5. 电力网络
- 所有发电厂产出的电力汇入统一电力网络
- 电力不足时按优先级断电：科研设施 > 维生系统 > 工业建筑
- 未来可扩展：区域电网隔离，局部电力传输损耗

## 七、起始定居、跨区域移动与开局引导（规划，尚未实现）

> 当前运行版本只实现 72 区域热力图、区域详情、区域建造和建筑工人分配。人口与大部分资源仍按全局池管理；所有区域从开局即可浏览，也没有首都区、勘探状态、迁徙队、运输路线或前哨补给。设置中的“启用教程提示”目前只保存选项，尚没有实际引导控制器。本章全部属于后续玩法目标，不能作为当前功能说明。

### 1. 开局身份与设计目标

- 玩家指挥的是行星上已经存在的原始文明群体，不是一支了解全球地理和矿藏的星际殖民队。“选择起始区域”代表选择这个文明最初生活和形成组织的区域，不是游戏开始后把人口瞬间传送过去。
- 开局必须先教会玩家完成一个最小但真实的生存循环：理解时间与暂停、选择定居环境、确认人口与食物、安排第一批岗位、建立最初的知识传递，再开始建设和勘探。
- 引导只解释文明当前可见的信息和已经解锁的操作。隐藏矿藏、未知科技、未来真实轨道、伤亡和灾害结果不得为了教学方便提前公开。
- 引导不得替玩家选择“最优解”，不得发放脱离模拟的免费资源，也不得用脚本强制完成实际系统尚未结算的任务。

### 2. 新宇宙创建与开局顺序

新游戏流程按以下顺序推进：

1. **命名宇宙**：校验名称与现有存档冲突。
2. **选择难度**：从版本化场景难度配置读取稳定纪元；规则层说明与文明知识分开。
3. **选择引导模式**：完整引导、精简提示或关闭引导。第一次游戏默认完整引导，之后沿用玩家设置但可随时更改。
4. **创建宇宙与初始存档**：生成场景、原始人口和候选起始环境，写入能够恢复开局阶段的“初始存档”。
5. **第 0 天区域观察**：模拟保持暂停，玩家在真实区域地表观测主页面与区域地图之间查看候选定居区。
6. **确认文明发源地**：显示已知优势、已知困难和未知项；确认后设置中心定居区与初始熟悉范围。
7. **引导完成首个生存循环**：玩家亲自进行人口、食物、教学、建造与观察操作，然后解除开局清单的强提示。

在简单、普通、困难模式中，引导期间不会额外扣除稳定纪元时间；极限模式也必须在玩家确认定居地之前保持第 0 天暂停，确认后才开始真实混沌模拟。关闭引导只关闭讲解与任务高亮，不能绕过定居区这一必要世界状态。

### 3. 起始区域选择与信息边界

- 场景生成器提供若干环境上可生存的候选中心区，但推荐算法只能使用文明当时可观察的数据：当前温度/光照、可见地形、水源或植被迹象、原始群体已有生活经验等。
- 候选卡片显示“我们知道什么、为什么可能适合、还不知道什么”，不能显示未勘探矿物精确值、未来恒星轨道或隐藏的长期安全评分。
- 推荐标签只表示基于已知信息较易起步，并明确列出依据和置信度；不能读取场景未来真值后把最佳区域暗中标出。
- 选择中心区后，其相邻且能够步行到达的若干区域构成**初始熟悉区**。熟悉区知道基本地形、常用路径和肉眼可见资源，但地下矿藏、精确储量和长期环境规律仍需勘探与记录。
- 确认前可以比较候选区；确认后更换文明发源地等同重新开局。游戏中的迁都属于后续高成本政策与物流行为，不能用观察区域选择器替代。

### 4. 完整开局引导阶段

引导使用事件驱动清单，不以“打开过某个页面”冒充掌握。每一步观察实际系统结果后完成：

| 阶段 | 引导内容 | 完成依据 |
|---|---|---|
| 规则与时间 | 区分稳定纪元规则倒计时、文明观测结论、暂停和时间倍率 | 玩家实际暂停/继续并查看两类信息说明 |
| 观察与定居 | 切换候选区域，阅读天空、地形、当前环境和未知项 | 玩家确认起始中心区 |
| 人口与生存 | 认识总人口、可用劳动力、食物/水、暴露人口和庇护能力 | 完成一项真实的生存岗位或人口安排 |
| 知识传承 | 指定讲述者/教师与学习者，理解教学会占用劳动时间 | 建立并成功运行第一项教学计划 |
| 第一项建设 | 查看材料、施工人力、地点和预期维护，选择当前真正需要的设施 | 一项合法建造命令进入施工状态 |
| 天空与预警 | 从本地区域观察真实天空，理解“看见天体”不等于能够预测灾害 | 完成一次观察记录；不要求解锁伤亡预测 |
| 勘探与出行 | 选择相邻未知区，配置队员、口粮、携带能力和预计路程 | 第一支勘探队安全出发或玩家明确暂缓 |
| 自主发展 | 汇总当前风险、知识缺口和可选方向，介绍如何重新打开引导手册 | 玩家关闭开局清单并进入常态 HUD |

若某一步因难度、区域条件或随机事件暂时无法完成，引导应说明缺少什么并允许暂缓，不得锁死其他已合法开放的界面。极限模式可以缩短讲解文字，但不能伪造安全环境或给予额外发展时间。

### 5. 引导交互规则

- **完整引导**提供可折叠任务卡、相关控件高亮、原因说明和下一步建议；只有需要确认不可逆选择时才使用模态层。
- **精简提示**不显示连续任务，只在玩家第一次进入系统、出现资源断供或长时间没有可用进展时给出一次性提示。
- **关闭引导**隐藏教学提示，但保留百科、术语解释、当前目标建议和必要的危险确认。
- 玩家可跳过单个非必要步骤、暂缓整组引导或彻底关闭；之后可从帮助/引导手册恢复。恢复时从已保存的实际完成状态继续，不重复扣资源或创建任务。
- 提示必须指出因果，例如“教师占用了 2 名劳动力，因此采集下降”，而不是只说“点击这里”。提示引用当前实时数值，数据变化后原地刷新。
- 同类提示具有冷却和“不要再提示”选项；暂停菜单、存档浏览器和紧急告警优先级高于普通教学气泡。
- 引导定义使用稳定任务 ID 和版本号。版本更新新增步骤时，不得把老存档已完成的操作全部重置；迁移器只补充确实未掌握的新概念。

### 6. 区域认知与勘探

每个区域分别保存认知状态：

| 状态 | 可见信息 |
|---|---|
| `UNKNOWN` 未知 | 仅可能知道大致方向，不显示详情 |
| `OBSERVED` 远观 | 粗略地形、天空可见信息和宽泛环境印象 |
| `FAMILIAR` 熟悉 | 常用路径、表面资源迹象、当前环境与生活经验 |
| `SURVEYED` 已勘探 | 在当前测量技术允许范围内显示资源种类、估算区间和路线风险 |
| `MONITORED` 持续监测 | 由驻点/仪器持续更新环境、库存、人口和预警数据 |

- 初始熟悉区从 `FAMILIAR` 开始，而不是无条件 `SURVEYED`。资源精度受工具、测量方法、记录制度和采样覆盖限制。
- 勘探队是实际人口组，携带食物、工具和记录载体，占用劳动力并沿区域邻接路线移动。队伍可能因极端温度、辐射、迷路、补给中断和灾害受损。
- 勘探结果记录的是当时认知和置信区间，不直接复制模拟内部的无限精度资源真值。更先进的地质、遥感和自动监测能力可提高精度并减少过期。

### 7. 跨区域移动、建设与物流

- 人口、勘探队、运输队和关键物资必须具有所在区域或行进路线；不能继续依赖全局人口池在任意区域瞬间分配工人。
- 路线基于 72 区邻接图，旅行时间和风险由距离、地形、当前环境、队伍速度、负重、补给和交通能力计算。跨区移动是有持续时间、可暂停/改道且可遭遇事件的任务。
- 早期文明依靠步行、背负和简易储藏，只适合熟悉区与相邻区域；畜力、道路、车辆、铁路、航空和自动运输随知识、材料、能源和工程化逐步出现。
- 资源首先进入所在地库存。跨区施工只有在人员、材料和维生补给实际到达后才能推进；成本上升来自运输量、损耗、路线维护和时间，而不是无条件套用 `3~5 倍` 人工倍率。
- 同一聚落内部仍可能简化短距离搬运，但“低成本”必须由连通道路、管线、仓储或步行范围解释。电网、供水和物流网络分别计算，不能用“全球运输科技”一次性取消所有空间约束。
- 区域建筑只能分配当地可用人口；跨区调动先生成迁徙/通勤任务，到达后才改变岗位。取消任务时保留队伍当前位置与已经消耗的补给。

### 8. 前哨、聚落与迁都

- 偏远区域首先建立需要持续补给的营地/前哨，容量由当地庇护、食物、水、仓储和通信决定，不使用固定“最多 2~3 座建筑”的任意上限。
- 前哨达到人口、维生、自给、交通和管理条件后可升级为常设聚落；断绝补给时按当地库存继续运行，并可能撤离或失联。
- 迁都需要选择目标聚落、转移组织人员和档案、建立通信与行政设施，并承担一段时间的协调损失。观察区域、当前建造区域和首都区是三个独立状态。

### 9. 存档状态

至少保存：

- `capital_zone_id`、`familiar_zone_ids`、各区域认知状态与认知数据版本
- 区域人口组、队伍位置/路线/目的地、行程进度、携带物资与状态
- 区域库存、运输任务、道路/管线/电网连接、前哨与聚落状态
- `guidance_version`、引导模式、当前阶段、已完成任务 ID、已关闭提示和暂缓原因
- 未完成的起始区域选择；读取“初始存档”后必须回到第 0 天选择流程，而不是默认区域 `0` 后直接运行

旧存档迁移时，现有全局人口和库存放入区域 `0` 的默认聚落，区域 `0` 设为首都与 `FAMILIAR`；不得复制到 72 个区域。旧设置中的布尔 `enable_tutorial=true/false` 分别迁移为完整引导/关闭引导。

### 10. 验收标准

1. 当前文档和 UI 明确标识该系统尚未实现；完成前不得把“启用教程提示”描述为可用的新手流程。
2. 新宇宙在玩家确认起始区之前保持第 0 天暂停，保存并读取后能继续同一步骤。
3. 候选推荐只使用文明可见数据；改变隐藏矿藏或未来轨道而保持公开输入相同时，推荐结果不得变化。
4. 完整、精简、关闭三种模式只改变教学呈现，不改变资源、轨道、科技、灾害概率或合法操作结果。
5. 引导任务根据真实信号完成；只打开人口、知识或建造页面不能伪造完成相应操作。
6. 勘探队和迁徙队实际占用人口、物资和时间；队伍到达前不能在目标区域分配工人或使用运输中的材料施工。
7. 跨区建设成本可由运输、损耗和维护逐项解释，不存在隐藏的固定距离倍率。
8. 跳过、关闭、恢复引导以及保存/读取不会重复发放资源、重复完成命令或丢失任务状态。

## 八、开局难度、稳定纪元与混沌转换（已实现）

> 当前运行版本已完成配置驱动难度选择、规定稳定星历、连续 N 体切换、规则 HUD、场景状态存档，以及文明观测预测与真实未来的接口隔离。现有 19 节点科技原型最多开放定性/区域预测；伤亡估算和知识损失能力只有在后续知识系统提供对应能力标签后才会开放，缺少能力时预测快照本身不包含这些字段。`SatelliteNetwork` 已提供可保存的部署/覆盖接口，但当前原型尚无火箭与卫星发射玩法，因此普通流程不会凭空获得卫星覆盖率。

### 1. 难度只规定“何时进入真实三体混沌”

新建宇宙时必须选择难度。标准难度不直接修改资源产量、人口生命值或研究速度，首先只控制稳定纪元长度，避免把“简单”偷换为纯数值加成。

| 模式 | 稳定纪元 | 说明 |
|---|---:|---|
| 简单 | 100 年 | 有完整的原始文明发展和知识基础设施建设期 |
| 普通 | 50 年 | 默认模式，需要较早建立观测与生存体系 |
| 困难 | 25 年 | 发展窗口紧张，必须取舍知识、工业和避难能力 |
| 极限 | 0 年 | 开局立即进入真实三体数值模拟 |
| 自定义 | 玩家输入 | 手动指定多少游戏年后进入混沌；范围暂定 `0~500` 年，最终上限由平衡测试确定 |

表中数值是默认设计值，不得硬编码在新游戏界面或 `ScenarioManager` 中。标准难度的 ID、显示顺序、稳定年数、默认选项，以及自定义模式的最小/最大年数，统一来自项目内的版本化“场景难度配置”资源。开发者可直接编辑该资源并运行校验，无需修改脚本，也不通过游戏内开发者模式或玩家设置暴露这些参数。

1 游戏年统一按 365 游戏天计算。创建新宇宙时，将所选预设当时的 `difficulty_id`、`stable_years`、配置版本和计算后的 `chaos_start_day` 固化进存档；后续修改全局难度配置只影响新开的宇宙，不得改变已有存档。自定义模式同样保存玩家最终输入的实际年数，而不是每次加载时重新读取上下限或默认值。

### 2. 稳定纪元采用明确的阶段式模拟

仅靠随机生成普通四体初值，无法严格保证“第 25/50/100 年前稳定、到点后才混沌”。因此开局采用两阶段模型：

#### 阶段 A：规定轨道的稳定纪元

- 一颗主恒星与行星构成解析/预设的稳定二体轨道；行星的季节、昼夜、光照和区域环境仍按该轨道正常计算。
- 另外两颗恒星位于遥远位置，沿场景规划器给出的规定轨道/接近轨迹运动；在稳定纪元内不向行星和主恒星施加会破坏稳定性的 N 体引力。
- 碰撞终局在稳定配置中应由场景验证保证不会提前发生，而不是每局依赖运气。
- UI 明确显示当前处于“稳定纪元”。玩家选择难度时知道预计混沌年份；文明能否科学地理解其原因和精确轨迹，仍取决于观测科技。
- 这是一段为玩法提供确定发展窗口的假模拟/解析星历，必须在开发文档和测试中明确，不得伪装成从开局起完整求解的 N 体物理。

#### 阶段 B：真实混沌纪元

- 当 `game_time >= chaos_start_day` 时，以规定星历该时刻的连续位置和速度为初值，一次性切换到现有 RK4 N 体引力模拟。
- 场景规划器在新游戏创建时就生成能于转换时形成有效三体系统的状态；转换不能瞬移天体、跳变速度或直接安排必然碰撞。
- 从转换帧开始，三颗恒星和行星完全服从同一套引力积分、碰撞与环境计算，不再为了难度脚本化后续结果。
- 相同难度、种子和玩家无关的初始配置应可复现；进入混沌后的微扰和玩家发展结果仍可产生分歧。
- 转换前后至少保存一个连续轨迹窗口，保证星图、地表天空和环境参数没有视觉断裂。

### 3. 混沌到来前的预警与真实性

- 难度选择给玩家的是“规则层面的安全窗口”，不是文明自动拥有的天文学知识。
- 原始文明只能看到远方亮星和缓慢变化；历法、长期观测、精密测角和数学模型逐步揭示它们正在接近。
- 观测质量足够时，UI 从模糊的“天象正在改变”逐步提升到区间预报；只有高质量观测网络才显示精确倒计时和风险范围。
- 简单/普通/困难模式可在规则 HUD 中保留难度倒计时，避免玩家因隐藏信息误解难度；世界内角色的科学结论与规则提示分层显示。

### 4. 轨道预测必须依赖观测基础设施

- 稳定纪元中的基础力学和轨道理论最多证明理想二体规律，不能自动授予真实三体长期预测加成。
- “理解引力/轨道”进入 `MASTERED` 后，仍需完成望远镜、时钟、精密测角、统计误差与计算方法等前置，才能开始实测预测。
- 高精度预测要求建设观测站并持续积累带时间戳的方向/距离数据；地面天气、视野和仪器误差影响数据质量。
- 卫星观测需要火箭、材料、能源、通信、遥测、轨道控制和计算设施。单颗卫星只增加有限覆盖，多星组网才能减少盲区并提高预报置信度。
- 自动化不是一次科技解锁：自动测量、数据清洗、轨道拟合、异常告警和卫星维护分别需要设备、软件/算法、供电和操作人员。
- 混沌开始后出现的真实多体偏差会提供新的科技线索，推动从二体理论转向多体数值方法；没有观测数据时，即使玩家知道节点存在，也不能完成工程化预测系统。
- 危机伤亡与知识损失预览读取同一套预测能力：没有 `casualty_estimation` 与人口/建筑脆弱性数据时，只能显示暴露数量，不能显示预计死亡数量；没有 `knowledge_loss_projection` 时，只能显示哪些载体处于风险中，不能给出节点退化概率。

### 5. 新游戏与存档字段

新建宇宙界面在命名之后进入难度配置，至少保存：

- `difficulty_id`：`easy/normal/hard/extreme/custom`
- `stable_years`、`chaos_start_day`
- `difficulty_config_version`：创建宇宙时使用的难度配置版本；标准模式同时保存预设快照
- `simulation_phase`：`STABLE_EPHEMERIS` 或 `CHAOTIC_NBODY`
- `scenario_seed`、规定星历参数、转换目标状态版本
- `chaos_started`、实际转换时间与转换事件是否已触发
- `hazard_forecasts`：文明已生成的公开预测、观测/模型版本、置信度、生成与失效时间；不得保存成可被 UI 读取的未来真实灾害答案

旧存档没有上述字段时，按其天体状态直接视为 `CHAOTIC_NBODY`，保持现有行为，不凭空补发稳定纪元。

### 6. 验收标准

1. 简单、普通、困难模式在指定年份以前不会因 N 体扰动或天体碰撞提前结束稳定纪元。
2. 到达指定时间的同一帧切换到真实 N 体积分，位置、速度、天空画面和区域环境连续。
3. 极限模式从第 0 天使用真实 N 体模拟，与当前原型行为一致。
4. 保存/读取稳定纪元和混沌纪元后，倒计时、规定轨道、种子和转换状态完全一致。
5. 仅掌握理论但没有观测站/卫星数据时，不获得高精度混沌轨道预测效果。
6. 自定义年数经过边界校验；负数、非数字和超上限输入不能开始游戏。
7. 修改项目内难度配置后，新游戏菜单和新建场景采用新数值；修改前的存档仍按其中固化的 `stable_years/chaos_start_day` 运行。
8. 难度配置缺失、预设 ID 重复、默认 ID 不存在或年数非法时，开发校验必须失败并给出具体字段，不允许静默回退到另一套硬编码年数。
9. 未掌握相应科技或缺少观测网络时，危机方案不得显示精确伤亡、受灾区域或知识退化概率；提升理论、观测数据和卫星覆盖后，信息按层级增加并始终带置信度。
10. 规则层的混沌日期不能向文明预测层泄露真实轨道；在同一低预测状态下反复切换避难方案，也不能通过数值变化反推出未观测灾害结果。
