## 1. scripts/simulation/three_body.gd — 三体运动模拟

`class_name ThreeBodySimulation extends RefCounted`

### 常量

| 名称 | 值 | 说明 |
|---|---|---|
| `G` | 1.0 | 简化引力常数 |
| `TRAIL_LENGTH` | 200 | 每颗星的轨迹队列长度 |

### 属性

| 名称 | 类型 | 说明 |
|---|---|---|
| `stars` | Array[StarData] | 4 天体（3 恒星 + 1 行星） |
| `time_scale` | float | 模拟时间倍率（默认 1.0） |

### class StarData

| 字段 | 类型 | 说明 |
|---|---|---|
| `mass` | float | 质量（恒星 500~1100，行星 1.0） |
| `position` | Vector3 | 当前 3D 坐标 |
| `velocity` | Vector3 | 当前速度 |
| `color` | Color | 显示颜色 |
| `radius` | float | 显示半径（缩放 0.5 后使用） |
| `is_planet` | bool | 是否为行星 |
| `trail` | Array[Vector3] | 轨迹队列（FIFO，max 200） |

### 方法

| 方法 | 参数 | 返回值 | 功能 | 调用方 |
|---|---|---|---|---|
| `_init()` | — | — | 调用 `_initialize_stars()` 生成初始配置 | GameState.new_game, GameState.from_dict |
| `_initialize_stars()` | — | — | 随机生成层级稳定 4 天体：内双星（互绕）+ 外第三星（绕双星质心）+ 行星（绕双星） | `_init()` |
| `compute_forces_for_state(positions)` | Array[Vector3] | Array[Vector3] | 遍历所有星对计算引力合力 = `G×mi×mj×r / dist^3`（用于 RK4 四步） | `update()` ×4 |
| `update(dt)` | float | void | RK4 四阶积分 + 1e-5 随机微扰 + 轨迹 push/pop | GameState.update |
| `has_collision()` | — | bool | 任意两天体中心距小于半径和时返回 true | GameState.update |
| `get_environment_params()` | — | Dictionary | 返回 {light_intensity, heat_level, temperature, radiation, stability} — 光照=Σ mass×10/(dist²+100)/8，温度=-273.15+光照×7000，辐射=Σ mass×200/dist^2.5，稳定性=1/(1+accel/0.1) | GameState.update, PlanetZoneManager |
| `_compute_stability(planet)` | StarData | float(0~1) | 行星所受合力加速度的倒数映射 | `get_environment_params()` |
| `get_stars_data()` | — | Array[Dictionary] | 每星 {position, mass, is_planet} | GameState.update, PlanetZoneManager |
| `get_planet_position()` | — | Vector3 | 行星坐标（遍历找 is_planet==true） | GameState.update |

## 2. scripts/simulation/planet_zones.gd — 行星区域系统

`class_name PlanetZoneManager extends RefCounted`

### 常量

| 名称 | 值 | 说明 |
|---|---|---|
| `LATITUDE_DIVISIONS` | 6 | 纬度分 6 行（每行 30°） |
| `LONGITUDE_DIVISIONS` | 12 | 经度分 12 列（每列 30°） |
| `TOTAL_ZONES` | 72 | 总区域数 |
| `TERRAIN_TYPES` | ["平原","高原","山地","峡谷","盆地","丘陵"] | 6 种地形 |
| `TERRAIN_RESOURCE_TABLE` | dict{str: dict} | 地形→{iron, copper, rare_mineral, fertility, algae} 基础系数 |
| `TERRAIN_THERMAL_MODIFIER` | dict | 地形温度修正：平原 0 / 高原 -6 / 山地 -10 / 峡谷 -2 / 盆地 +3 / 丘陵 -3 |

### 属性

| 名称 | 类型 | 说明 |
|---|---|---|
| `zones` | Array[PlanetZone] | 72 个区域 |
| `rotation_angle` | float | 当前自转角度（度，fmod 360） |
| `rotation_speed` | float | 自转速度（度/游戏天，默认 15） |
| `thermal_inertia` | float | 热惯性系数（默认 0.08） |
| `diffusion_rate` | float | 大气扩散率（默认 0.15） |
| `dark_side_scatter` | float | 暗面散射因子（默认 0.25） |
| `light_to_temp_scale` | float | 光照→温度转换因子（默认 500，经 `_init_zone_temperatures` 校准） |
| `light_norm_divisor` | float | 光照归一化除数（默认 1.0，经校准） |
| `base_temperature` | float | 基础温度 -273.15°C |

### class PlanetZone

| 字段 | 类型 | 说明 |
|---|---|---|
| `zone_id` | int | 0~71 |
| `lat_index`, `lon_index` | int | 行列索引 |
| `lat_center`, `lon_center` | float | 中心经纬度 |
| `lat_bottom`, `lat_top`, `lon_left`, `lon_right` | float | 边界 |
| `terrain_type` | String | 6 种地形之一 |
| `temperature` | float | 当前温度 °C |
| `radiation` | float | 当前辐射值 |
| `light_intensity` | float | 当前光照（0~1） |
| `resource_deposits` | Dictionary | {iron, copper, rare_mineral} 系数 |
| `fertility` | float | 肥沃度 |
| `algae_density` | float | 藻类密度 |
| `building_ids` | Array[int] | 该区建筑 ID 列表 |
| `area_weight` | float | 面积权重（cos(lat)） |
| `get_work_efficiency()` | float | 委托静态方法 `_calc_work_efficiency(temperature)` |

### 方法

| 方法 | 参数 | 返回值 | 功能 | 调用方 |
|---|---|---|---|---|
| `_init(env_config)` | Dictionary | — | 读取 rotation_speed/thermal_inertia/diffusion_rate/dark_side_scatter → `_init_zones()` → `_build_neighbor_cache()` | GameState.new_game |
| `_init_zones()` | — | void | 6×12 循环：面积权重=cos(lat) → 随机地形 → 资源含 ±30% 浮动 | `_init()` |
| `_build_neighbor_cache()` | — | void | 每区 ≤4 邻居（左右经度 wrapi，上下纬度无环绕），存 `_neighbor_cache[zone_id] = [neighbor_ids]` | `_init()` |
| `_get_zone_normal(zone)` | PlanetZone | Vector3 | 球面经纬→笛卡尔单位法线（含自转 `rotation_angle` 偏移） | 区域环境计算 |
| `update(dt, time_scale, stars_data, planet_pos)` | float, float, Array, Vector3 | void | 自转角度更新 → `_collect_active_stars()` → `_compute_zone_environments()` | GameState.update |
| `initialize_temperatures(stars_data, planet_pos)` | Array, Vector3 | void | 设定目标温度（跳过热惯性）+ 10 轮扩散 | GameState._init_zone_temperatures |
| `_collect_active_stars(stars_data, planet_pos)` | Array, Vector3 | Array[Dictionary] | 排除行星 → 返回 [{direction, distance, mass}] | 区域环境计算 |
| `_compute_zone_environments(active_stars, dt)` | Array, float | void | 逐区光照（法线·星光方向 × 散射因子）+ 温度趋近（热惯性）+ 辐射 + 扩散 | `update()` |
| `_apply_diffusion(game_days)` | float | void | 每区温度向其邻居均温靠拢（factor = diffusion_rate × abs(dt), clamped 1.0） | `_compute_zone_environments()`, `initialize_temperatures()` |
| `get_zone(zone_id)` | int | PlanetZone or null | 按 ID 查找 | EntityManager, GameState, UI |
| `get_zone_at(lat, lon)` | float, float | PlanetZone or null | 按经纬度查找 | UI |
| `get_average_environment()` | — | {temperature, radiation, light_intensity} | 面积加权平均 | GameState 多处 |
| `get_zone_environment(zone_id)` | int | Dictionary | 完整区域数据（含建筑数、资源、效率） | UI |
| `get_all_zones_summary()` | — | Array[Dictionary] | 72 区简要数据（id, lat_i, lon_i, temp, rad, light, terrain, buildings, fertility, algae, deposits） | GameState.get_state, UI |
| `get_illuminated_zones()` | — | Array[int] | light > 0.05 的 zone_id 列表 | — |
| `add_building_to_zone(zone_id, building_id)` | int, int | bool | 追加到 zone.building_ids | DecisionManager._execute_construction |
| `remove_building_from_zone(zone_id, building_id)` | int, int | void | 从 building_ids 移除 | — |
| `get_state()` | — | Dictionary | 序列化：rotation_angle + light_to_temp_scale + light_norm_divisor + zones 列表 | GameState.to_dict |
| `load_state(data)` | Dictionary | void | 反序列化恢复 rotation_angle / 地形 / 温度 / 建筑 / 资源 | GameState.from_dict |

### 静态方法

| 方法 | 功能 |
|---|---|
| `_calc_work_efficiency(temperature)` → float | -10~40°C=1.0；<-80 或 >100°C=0.0；中间线性 |

### 11.5 研究、工程化与传承项目

#### 11.6.2 `EducationSystem`

`EducationSystem` 不拥有独立人口池。教师和学生必须是 `EntityManager`/未来人口子系统中的实际人口分配，教学时间与生产、研究和建造工时竞争。

`TeachingPlan` 建议结构：

```gdscript
{
	"plan_id": "plan:basic_literacy_001",
	"curriculum_id": "basic_literacy",
	"teacher_ids": [],
	"student_group_ids": [],
	"hours_per_day": 4.0,
	"material_allocation": {},
	"facility_ids": [],
	"practice_building_ids": [],
	"emergency_course": false,
}
```

拟议接口：

- `validate_plan(plan)`：检查教师是否掌握课程、人口是否重复占岗、教材/场地/实践设施是否可用。
- `start_plan(plan)` / `pause_plan(plan_id)` / `cancel_plan(plan_id)`：管理持续教学计划。
- `update_day(context)`：按教师掌握度、师生比、课时、识字/语言、教材、场地和实践条件输出 `TeachingResult`。

#### 11.6.3 `PreservationAllocator`

避难容量不得压缩成单一人数。设施快照至少提供：

```gdscript
{
	"shelter_id": "building:deep_shelter_012",
	"usable_volume_m3": 0.0,
	"berths": 0,
	"life_support_people": 0,
	"food_water_person_days": 0.0,
	"dry_archive_volume_m3": 0.0,
	"heavy_storage_mass_kg": 0.0,
	"continuous_power_kw": 0.0,
	"environment_control_level": 0.0,
}
```

`PreservationPlan` 保存候选人口组、教师/专家、学徒、档案批次、样机/模具/关键工具、领域/载体权重、手动锁定项和应急姿态。人员始终只占一个人口名额；教师身份作为该人员的知识属性参与收益计算，不能另生成“教师单位”。

拟议接口：

| 方法 | 功能 |
|---|---|
| `preview_plan(plan, shelters, forecast_snapshot)` | 返回确定的容量占用/未安置对象，并且只在预测快照允许时附加伤亡区间与知识衰退风险 |
| `validate_plan(plan, shelters)` | 检查人员重复、对象不存在、容量维度、供电及手动锁定冲突 |
| `commit_plan(plan_id)` | 冻结已确认方案，供灾害结算读取；不得在此时直接杀伤人口或知识 |
| `resolve_plan(plan_id, hazard_outcome)` | 依据同一灾害结果生成实际 `PreservationResult`，禁止再次随机抽取灾害强度 |
| `get_state()` / `load_state(data)` | 保存方案、档案/样机位置、确认状态和已结算来源 ID |

`forecast_snapshot` 只能由 `HazardForecastService` 产生，且允许为 null。`PreservationAllocator` 不得读取 `ScenarioManager` 的未来位置、场景种子或真实灾害强度来补齐未知字段。null/低层级预测下仍返回确定的装载事实，但 `estimated_casualties`、`affected_zone_ids`、`knowledge_degradation_probability` 等字段必须缺失或明确为未知，不能填入内部真值后仅在视觉上遮挡。

`PreservationResult` 至少返回幸存人口 ID/分组、幸存教师与学徒、幸存档案批次、幸存实物、各容量实际占用、未安置对象、实际伤亡和面向 `KnowledgeInheritance` 的损失向量。结果必须由给定方案与已经发生的 `HazardOutcome` 确定性复现；实际结果与此前预测不同属于正常玩法结果。

#### 11.6.4 UI 与验收约束

- 知识政策页显示四条分支、总体重视度、载体/领域细分、教学岗位和避难方案，不展示尚未具备前置能力的未来制度细节。
- 危机预览始终显示已纳入/未纳入人口、其中教师/专家与学徒、纸质档案体积、实物质量/体积和各容量瓶颈；不得把“纳入避难方案”直接标成“必定获救”。
- 预计伤亡、受灾区域和知识降级按预测层级逐项出现。无预测时显示未知；只有定性能力时显示文字风险；定量能力成熟后才显示区间、情景和置信度，不显示虚假的单一精确数字。
- 相同人员不能同时作为普通人口和教师占用两个床位；纸质档案不能消耗生命保障名额，但必须消耗真实干燥体积和环境控制。
- “知识优先”不能突破容量或提供知识加成，只改变短缺时的选择顺序；“生命优先”也不能自动保留无人掌握且无记录的知识。
- 仅保存文献、仅保存教师、同时保存教师和可实践样机三种方案应产生不同且可测试的传承结果。
- 旧存档中的避难所和人口必须由迁移器补充保守默认容量与空政策状态，不得因缺少新字段加载失败。
- 测试需保证低预测状态下预览字典本身不含真实伤亡/轨道字段；不能只测试控件隐藏。对同一预测快照切换不同方案时，只能改变由方案本身可推导的暴露和容量信息。

| `get_selectable_presets()` | — | Array[DifficultyPreset] | 按 `sort_order` 返回只读菜单数据 |
| `get_preset(id)` | StringName | DifficultyPreset/null | 精确按稳定 ID 查找，不按显示文字查找 |
| `create_snapshot(id, custom_years)` | StringName, float | Dictionary | 统一校验并返回配置版本、ID、实际年数、每年天数和混沌日 |

`create_snapshot()` 输出至少包含：

```gdscript
{
	"difficulty_config_version": 1,
	"difficulty_id": "normal",
	"stable_years": 50.0,
	"days_per_year": 365.0,
	"chaos_start_day": 18250.0,
}
```

配置文件缺失或 `validate()` 失败时，新游戏界面必须显示开发配置错误并阻止创建宇宙。禁止静默回退到 `ScenarioManager`、UI 或测试脚本中的另一套年份常量；否则开发者修改数据时无法确定实际生效来源。

#### 11.7.2 `ScenarioManager`

拟议枚举：

```gdscript
enum SimulationPhase {
	STABLE_EPHEMERIS,
	CHAOTIC_NBODY,
}
```

核心状态：

| 字段 | 类型 | 说明 |
|---|---|---|
| `difficulty_id` | String | easy/normal/hard/extreme/custom |
| `difficulty_config_version` | int | 创建宇宙时采用的难度配置版本 |
| `stable_years` | float | 规则指定的安全发展年数 |
| `days_per_year` | float | 创建时固化的游戏年换算 |
| `chaos_start_day` | float | `stable_years * days_per_year`，创建时计算并固化 |
| `simulation_phase` | SimulationPhase | 当前轨道提供者 |
| `scenario_seed` | int | 可复现场景种子 |
| `ephemeris_state` | Dictionary | 规定星历参数和版本 |
| `chaos_started` | bool | 防止重复转换/事件 |
| `actual_transition_day` | float | 实际转换帧的游戏时间 |

拟议方法：

| 方法 | 功能 |
|---|---|
| `create_scenario(difficulty_snapshot, seed)` | 接收已校验且可序列化的预设快照，生成稳定星历与转换目标 |
| `get_celestial_snapshot(game_time)` | 从当前阶段返回统一位置/速度/质量/半径快照 |
| `update(game_time, dt)` | 推进规定星历或真实 N 体，并在阈值帧转换 |
| `_transition_to_nbody(snapshot)` | 用连续位置和速度初始化 RK4，设置一次性状态并发事件 |
| `validate_stable_window()` | 离线/测试验证指定年份前轨道稳定且无碰撞 |
| `get_state()` / `load_state(data)` | 保存难度实际年数、配置版本、种子、阶段、星历和转换状态 |

`ScenarioManager` 不持有标准难度映射，也不在加载存档时重新查询全局难度资源。配置修改只影响之后创建的宇宙；旧存档始终使用已保存的 `stable_years/days_per_year/chaos_start_day`。旧存档没有 `scenario` 时直接包装当前天体为 `CHAOTIC_NBODY`。

配置测试至少覆盖：资源可加载、所有 ID 唯一、默认 ID 可选、年份有限且非负、自定义范围有效、`create_snapshot()` 换算正确；另以修改后的临时资源创建新场景，并验证修改前存档的倒计时保持不变。

### 11.8 观测与卫星网络

轨道预测的拟议输入不再只是科技布尔值：

```gdscript
prediction_capability = f(
	theory_capability,
	observation_data_quality,
	time_baseline,
	spatial_coverage,
	compute_capacity,
	instrument_calibration,
)
```

`ObservationNetwork` 保存观测站视野、天气、仪器、人员、误差和带时间戳数据；`SatelliteNetwork` 保存卫星轨道、传感器、通信、供电、维护和覆盖率。自动化分别作用于采集、清洗、拟合、告警和维护，不能用一个全局布尔值代替。

#### 11.8.1 `HazardForecastService`

计划文件：`scripts/simulation/hazard_forecast_service.gd`。职责是生成文明当下能够知道的危机预测，不负责推进真实轨道，也不负责灾害结算。

拟议预测层级：

```gdscript
enum ForecastLevel {
	NONE,
	QUALITATIVE_WARNING,
	REGIONAL_RISK,
	QUANTITATIVE_IMPACT,
	HIGH_PRECISION_PROBABILISTIC,
}
```

层级上限由知识能力标签控制：

- `hazard_warning`：允许定性预警。
- `regional_hazard_projection`：允许公布可能受灾区域和宽时间窗。
- `casualty_estimation`：允许结合人口、避难所和建筑脆弱性给出伤亡区间。
- `knowledge_loss_projection`：允许结合教师、档案、样机和节点传承状态给出退化风险。

标签是必要条件而非完整结果。实际层级和置信度还读取观测时间跨度、测量误差、仪器校准、卫星覆盖、计算能力、环境模型，以及人口/建筑/档案数据完整度。理论解锁但没有数据时，应返回较低层级或更宽区间。

`HazardForecastSnapshot` 建议结构：

```gdscript
{
	"forecast_id": "forecast:00042",
	"generated_game_day": 1200.0,
	"source_observation_version": 18,
	"model_capability_version": 4,
	"level": ForecastLevel.REGIONAL_RISK,
	"confidence": 0.32,
	"valid_until_game_day": 1230.0,
	"known_fields": ["risk_trend", "time_window", "possible_zone_ids"],
	"risk_trend": "rising",
	"time_window": {"earliest": 1220.0, "latest": 1300.0},
	"possible_zone_ids": [12, 13, 24],
	"scenario_ranges": [],
	"assumptions": [],
}
```

未解锁字段不写入快照。达到更高层级时才可增加 `casualty_range`、`knowledge_loss_ranges`、区域危害强度分布等内容；所有数值预测必须附带范围、置信度、生成时间和主要假设。

拟议接口：

| 方法 | 功能 |
|---|---|
| `build_forecast(knowledge_view, observation_data, infrastructure, census_snapshot)` | 仅用文明可访问输入生成新预测快照 |
| `get_public_snapshot()` | 返回已经按能力裁剪的不可变快照，供危机 UI 和保存分配器使用 |
| `is_stale(snapshot, current_context)` | 判断观测、模型、人口或时间变化是否使预测过期 |
| `compare_plans(plans, forecast_snapshot)` | 在同一公开预测分布下比较方案；不访问真实未来 |
| `get_state()` / `load_state(data)` | 保存预测来源、层级、区间、置信度和失效状态 |

禁止依赖：`ScenarioManager` 的未来天体快照、规定星历未来段、场景种子、尚未发生的 `HazardOutcome`。预测服务只可接收观测系统公开的历史/当前测量；模拟真值即使已经在内存中，也不能作为文明预测输入。

规则 HUD 的 `chaos_start_day` 与 `HazardForecastSnapshot` 是两套信息。前者是难度承诺，可以告诉玩家安全窗口何时结束；后者是文明科学认知，决定是否知道恒星轨迹、受灾区域和伤亡。两者必须使用不同字段和 UI 标签。

测试至少覆盖：

- `NONE` 层输出不包含区域、伤亡或知识损失字段。
- 只有理论、没有观测数据时不能越级生成定量结果。
- 增加观测基线、校准和卫星覆盖后，允许提升层级或收窄区间。
- 相同公开输入生成可复现预测；真实场景种子不同但观测尚不可区分时，公开快照不得泄露差异。
- 预测与实际 `HazardOutcome` 可以不一致，灾害结算仍只执行一次真实结果。

### 11.9 存档迁移顺序

建议目标 schema：

1. `save_schema_version=2`：加入 `observed_zone_id`，旧档回退 `0`。
2. `save_schema_version=3`：加入知识/发现/项目/传承、知识政策、教育和保存方案状态；旧 17 节点经显式映射转换，旧避难所补充保守容量。
3. `save_schema_version=4`：加入 scenario、难度配置版本、观测网络与文明危机预测快照；旧档阶段设为 `CHAOTIC_NBODY`，预测状态默认 `NONE`。

迁移必须逐版本执行、可重复测试、失败时保留原文件；在发布迁移前仍遵守 `res://saves/` 开发存储规则。
