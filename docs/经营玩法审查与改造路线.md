# 经营玩法审查与改造路线

审查日期：2026-07-27  
状态：策划基线，本文所列项目不代表已经实现。  
范围：当前 Godot 版本的核心循环、科技与知识、区域经营、危机处理、信息反馈、操作负担、节奏与终局。  

> 本文负责解释当前版本“为什么能运行但还不够好玩”，并规定经营玩法的改造优先级、目标体验和验收标准。具体玩法规则仍以[游戏设计文档](游戏设计文档.md)为最高来源；底层因果、物理守恒和架构债务由[架构与真实性审查](架构与真实性审查.md)维护。

## 1. 总体判断

项目已经具备有辨识度的硬科幻文明模拟底座：

- 恒星、行星、区域环境和稳定纪元—混沌纪元转换由真实模拟状态驱动；
- 文明只能使用当时能够观测、记录和理解的信息，规则层真相不直接泄露给文明；
- 知识不是普通解锁列表，而有发现、研究、应用、教学、保存和退化过程；
- 人口、设施、物资、地点与时间被设计为真实约束；
- 玩家进行文明尺度的宏观调控，而不是逐个居民微操。

当前主要问题不是内容不足，而是系统没有共同闭合成强经营循环：

1. 玩家等待的时间多于需要作出取舍的时刻；
2. 屏幕展示的状态多于能够追溯的变化原因；
3. 地图上的区域多于具有真实后果的区位选择；
4. 科技节点多于可供玩家选择的研究方法和工程方案；
5. 三体世界能够运动和变化，但危机尚未稳定形成“预测—准备—冲击—损失—恢复”的可重复玩法；
6. 游戏有长期模拟，却缺少清晰的阶段目标、失败边界和科技终局。

因此，后续阶段不应优先扩充资源、建筑或科技节点数量，而应先让已有系统互相产生清晰、可操作、可复盘的因果。

## 2. 必须保持的设计边界

改造不得以降低主题辨识度为代价。以下原则保持不变：

1. **科技路线是文明发展的主轴。** 科技应改变文明能够观测、推断、组织、建造和保存什么，而不是只提供抽象产量倍率。
2. **三体混沌是机制，不是剧情贴图。** 危机必须来自真实天体与环境状态；剧情可以解释结果，但不能替代模拟结果。
3. **预测永远带有信息边界。** 玩家只能看到文明当时有能力获得的预测、误差和条件风险，不能得到隐藏真值。
4. **所有决策落到真实载体。** 人口、岗位、设施、材料、能量、档案、样机、路线、地点和时间都必须有来源和占用。
5. **维持宏观管理。** 早期允许少量手工分配以建立理解，后期应由行政、通信和自动化科技解锁规则、模板和批量调度。
6. **不以普通战争和英雄单位填充玩法。** 项目的主要冲突是文明认知能力、生产组织与不可完全预测的自然环境之间的冲突。

## 3. 当前核心痛点

### 3.1 生存机制与核心主题发生反转

当前正常活动人口没有与脱水人口对等的区域环境暴露结算；人口热、冷和辐射损失主要经由脱水/保存分支的 `_process_storage_damage()` 处理。与此同时，饥饿损失会保留最后一名人口，缺少可信的文明灭绝条件。

直接后果是：

- 全民脱水可能比继续暴露在极端环境中更危险；
- 庇护所、维生设施和脱水仓没有形成相互可比较的生存方案；
- 玩家很难从伤亡结果理解自己之前的准备是否有效；
- 除天体碰撞外，文明长期失去维生能力也不一定形成明确失败。

这是最高优先级问题。只要该反转存在，继续扩展危机种类或避难设施只会放大错误因果。

### 3.2 有预测界面，但没有完整危机结算

当前已有环境状态、文明预测和保存方案预览，但普通玩法尚未稳定贯通以下过程：

1. 从真实模拟状态形成一个有开始、峰值和结束范围的危险事件；
2. 玩家在预测失效前承诺人员、设施、物资与知识载体；
3. 方案锁定并产生机会成本；
4. 危机只结算一次真实结果；
5. 人口、建筑、物流、能源、档案和知识分别受损；
6. 危机结束后形成因果明确的复盘和恢复选择。

因此，三体模拟目前更接近高质量背景系统，而不是持续驱动经营决策的发动机。

### 3.3 区域丰富，但地方经营的真实性不足

当前区域经济仍有全局结算后事后分账的路径，远区建筑的投入品、燃料和食物未完全通过地方库存与运输逐笔支付。电力也未严格拆分即时功率与储能。部分移动时间固定，地形、环境、负载和交通能力尚未共同决定行程风险。

玩家因此可能发现：

- 同类建筑建在不同区域，长期运行差异不够明显；
- 运输和迁徙更像任务进度，而不是生产网络的一部分；
- 144 区主要增加浏览量，没有等比例增加空间策略；
- 建造地点、庇护地点和能源地点之间缺少必须权衡的连接。

首都候选说明目前还会强调光照对采集/耕作、山地对旅行/建设的影响，但实际生产主要读取藻类密度与肥沃度，移动又仍使用固定分段耗时。界面承诺的因果和模拟实际使用的因果不一致，会使玩家觉得选择“似乎重要但结果没有区别”。

### 3.4 科技语义丰富，但研究行为偏浅

知识系统已经区分发现、传闻、洞见、研究、掌握、应用和退化，这是项目最应保留的特色。但玩家的主要操作仍常被压缩成：

```text
等待被动线索 → 点击节点 → 等待研究 → 点击工程化 → 获得建筑或效果
```

现有研究与工程项目缺少足够的资源竞争、设施争用、实验路线、失败信息和项目管理。部分能力标签没有实际消费方，最终聚变科技也没有进入可建设、可运营、可影响终局的工程闭环。

结果是科技树看起来很深，但玩家没有充分体验科学活动中的核心取舍：

- 先扩大观测覆盖，还是提高单点精度；
- 先验证模型，还是直接投入风险更高的工程原型；
- 将稀缺人才用于研究、教学、生产还是危机准备；
- 保留理论记录、实验数据、工程样机还是熟练人员；
- 接受更早但更模糊的预警，还是等待更精确但更晚的结论。

### 3.5 信息很多，但不是决策仪表盘

主界面以库存绝对值为主，缺少每日净变化、可维持天数、供需缺口、来源分解、劳动力占用和趋势预测。开局资源压力因此很难被及时理解。

项目完成、远征抵达、预报过期、设施停工和知识退化也没有统一的持久事件流与可配置暂停规则。高速推进时，玩家容易错过自己行为的结果，只能从总量变化反推发生了什么。

以当前默认开局为例，约 100 人拥有 300 食物、每日基础消耗约 10；确认首都后模拟会自动继续。在没有“可维持天数”提示时，玩家可能在五倍速下只用约六秒就耗尽初始储备。这不是有意义的困难，而是信息与暂停规则造成的开局操作陷阱。

经营界面必须优先回答：

1. 现在最紧迫的问题是什么；
2. 它为什么发生；
3. 如果不处理，何时会造成后果；
4. 哪些命令能够改变它；
5. 命令会占用什么，并推迟哪些其他目标。

### 3.6 操作随规模增长，但组织能力没有同步成长

区域详情同时承载全局概览、人口分配、迁徙、运输、聚落、建筑和施工操作。`±1`、`±10`、填满与清空适合原始聚落，但文明扩大后会形成重复点击。

全屏子界面主要返回主界面而非保留上下文的导航栈，区域详情又在同一滚动栏混合文明级、区域级和建筑级命令。知识制度一旦实施后缺少持续预算调整；教学计划缺少清晰的列表、暂停、取消和优先级管理；多个长期计划可能不结束地占用人口而不易被发现。

合理的解决方式不是从开局提供全自动化，而是让管理抽象本身成为科技与制度进步：

- 原始聚落：直接分配少量人员；
- 记录与基础行政：设置岗位目标；
- 通信与统计：设置区域优先级和缺口告警；
- 计算与自动化：使用生产模板、补员规则和危机预案；
- 高级文明：按目标和约束调度，不再逐建筑点击。

### 3.7 长期节奏与终局不足

难度目前主要改变稳定纪元持续时间。稳定阶段缺少足够的中期节点与可结算危机，混沌阶段又可能以天体碰撞突然结束。游戏尚无明确的文明长期胜利目标，科技树末端也缺少足以承载终局的工程。

这会形成“前期学习界面、中期挂机成长、后期突然结束”的风险。

## 4. 目标经营循环

全项目后续玩法应收束到以下循环：

```text
观测与记录
    ↓
形成带置信区间的情景预测
    ↓
选择科技、工程、教育或制度方案
    ↓
承诺真实的人力、材料、设施、能源和时间
    ↓
乱纪元冲击真实结算
    ↓
复盘预测误差、伤亡、设施与知识损失
    ↓
恢复生产、修正模型并进入下一轮
```

每一轮都应同时回答三个问题：

- **科学问题**：文明知道了什么，还不知道什么；
- **经营问题**：有限人员和资源优先投向哪里；
- **生存问题**：哪些人、设施和知识可以被保护，哪些风险必须接受。

科技路线通过控制以上三个问题成为真正主轴，而不是独立于经营循环的解锁菜单。

## 5. 科技主轴的具体改造

### 5.1 科技应解锁新的行为能力

| 科技方向 | 应解锁的玩家能力 |
|---|---|
| 天空观测 | 发现更多天体信号、延长观测窗口、区分天体来源 |
| 标准测量 | 显示误差、校准不同观测站、减少错误趋势 |
| 时间与历法 | 建立可比较的长期序列，提高周期判断可信度 |
| 数学与统计 | 比较多个情景、估计置信区间、识别模型偏差 |
| 计算技术 | 增加情景数量、预测时长和自动告警，但消耗设备与能源 |
| 材料与工程 | 建造可承受特定温度、辐射和压力范围的真实设施 |
| 教育与记录 | 扩大知识承载人口、复制档案、降低灾后断层风险 |
| 行政与通信 | 解锁区域命令、岗位目标、物流优先级和信息时效 |
| 自动化 | 解锁调度规则、生产模板和危机预案，不直接凭空增加产量 |
| 聚变与高能工程 | 支撑长期避难、全球观测或离开行星的终局工程 |

### 5.2 研究项目必须成为可管理对象

科技界面至少应持续显示：

- 当前假说与证据缺口；
- 可选观测、实验或原型路线；
- 所需人员、设施、材料、能源和预计时间；
- 设施冲突和机会成本；
- 成功、部分成功和失败分别会提供什么信息；
- 研究完成后哪些玩法系统会真实消费该能力；
- 后续工程化、教学和维护要求。

玩家必须能够查看、调整、暂停或取消研究、工程和教学项目。设施存在不等于无限共享，同一实验室、观测站或计算设备必须具有容量约束。

### 5.3 控制科技树继续扩张

在新增节点前，每个节点必须至少拥有一个可验证的玩法消费方。只描述世界观、没有玩家行为或模拟效果的节点，应暂缓加入正式路线。

每项主要科技完成后，玩家应在一到两个正常操作周期内看到至少一种变化：

- 新信息；
- 新命令；
- 新工程；
- 新的风险控制方法；
- 更高层级的管理抽象；
- 对既有错误模型的修正。

## 6. 分阶段改造路线

### P0：闭合一次真实的乱纪元危机

#### P0-1 区域人口暴露与庇护

- 正常活动人口按所在区域承受温度、辐射、食物、空气和维生失败；
- 脱水人口按储存位置、仓体容量、供能、屏蔽和维护状态承受风险；
- 庇护所只保护实际进入并获得维生资源的人口；
- 活动、就地庇护、迁移和脱水形成可比较但没有绝对正确答案的方案；
- 文明能够因人口归零或不可恢复的维生断裂而失败。

验收标准：

1. 同一场危机下，不同区域、设施和人口方案产生可解释的不同结果；
2. 脱水不会因为进入另一条伤害分支而天然比暴露更危险；
3. 伤亡报告能逐项指出暴露来源、保护来源和关键短缺；
4. 无保护人口不能依靠实现缺口免受极端环境伤害。

#### P0-2 危机预测、承诺与结算

- 真实模拟生成危险窗口和最终结果；
- 文明预测只保存观测版本、模型版本、区间与置信度；
- 玩家能比较多个方案，但必须在截止时间前确认；
- 确认后锁定人口、床位、运输、档案、样机、食物和能源；
- 真实结果只结算一次，不因切换界面或读取预览重新生成；
- 危机后生成预测—实际对比、损失来源和恢复建议。

验收标准：

1. 信息不足时不会显示隐藏真值；
2. 提升观测与计算能力会改变预测质量，而不会直接降低真实灾害；
3. 两个不同准备方案能够在同一真实灾害中产生不同损失；
4. 玩家能从复盘理解至少一个“如果此前改变某项投入，结果会不同”的因果。

#### P0-3 地方资源与能源因果

- 生产先进入当地库存，投入也从当地或在途库存支付；
- 运输任务携带明确货物并占用人员、载具、补给和路线容量；
- 功率供需使用 kW，储能使用 kWh；
- 按区域电网、线路容量和供电优先级结算；
- 施工劳动与运行岗位分开，所有实体工程需要施工人员；
- 建筑具有最低维护、备件和故障状态。

验收标准：

1. 切断一条运输或供电连接会在正确区域造成可追溯后果；
2. 远区建筑不能使用没有送达的全局物资；
3. 电力不足时按玩家设定的维生、研究、工业优先级停机；
4. 文明总账严格等于各地库存、在途货物和已承诺物资之和。

#### P0-4 建立至少一条科技终局

首个终局建议选择一条作为完整纵向切片：

- 聚变驱动的长期行星避难体系；
- 多层轨道观测与预警网络；
- 以恒星际逃亡为目标的长期工业计划。

终局必须经过理论、观测、工程原型、材料、能源、人员训练、建设和长期维护，不允许以单次科技解锁直接获胜。

### P1：使经营状态可读、可控、可扩展

#### P1-1 文明驾驶舱

主 HUD 的核心资源采用“库存 + 净变化 + 可维持时间”表达，例如：

```text
食物：300（-14/日，按当前净消耗可维持 21 日）
电力：供给 15 / 需求 24 kW，储能 42 kWh
人口：100＝生产 16、研究 5、教育 9、迁徙 5、危机准备 8、空闲 57
```

点击或悬浮后显示：

- 今日生产和消费来源；
- 与昨日相比发生变化的原因；
- 已承诺但尚未消费的数量；
- 按当前趋势预计出现缺口的日期；
- 能够直接打开相关区域、设施或项目的入口。

#### P1-2 统一活动队列与事件流

统一显示：

- 研究、工程、教学和制度筹建；
- 建筑施工、维修和停工；
- 迁徙、运输、勘探和抵达；
- 预测生成、更新和失效；
- 危机预案确认截止时间；
- 知识退化、设施故障和资源告警。

设置允许分别启用“完成时暂停、重大警告时暂停、队伍抵达时暂停、危机开始时暂停”。事件必须保留在历史记录中，不能只显示几秒后消失。

#### P1-3 区域地图转为经营地图

在现有温度、辐射和光照层之外，增加：

- 人口与庇护容量；
- 食物净平衡和库存天数；
- 发电、用电、储能和电网连接；
- 地方库存、运输路线和在途任务；
- 施工、维护和故障；
- 聚落等级与可用岗位；
- 观测覆盖、知识载体和危机概率。

地图层只显示文明已经掌握的信息，过期情报要标明观测时间和可信度。

#### P1-4 让组织能力减少重复操作

- 早期继续保留直接人员增减；
- 基础行政解锁岗位目标人数；
- 统计能力解锁“维持最低食物盈余”等规则；
- 通信能力允许跨区调度并引入信息时效；
- 自动化允许复制聚落模板、按优先级补员和执行已确认的危机预案。

任何自动化都必须由已有能力、人员、设备和通信条件支撑，并允许玩家查看它为什么作出某次调整。

### P2：重构节奏、阶段目标与内容组织

#### P2-1 稳定纪元仍然需要经营压力

稳定纪元不应是长时间等待混沌日期。应由真实环境和文明状态形成较小但可恢复的前线：

- 异常热浪或寒潮；
- 短期高辐射窗口；
- 地方食物和能源危机；
- 运输中断与设施故障；
- 教育中断、档案损毁和知识退化。

这些事件用来教会玩家如何观测、准备和复盘，并逐步暴露三体系统的异常。

#### P2-2 混沌纪元形成多轮升级

混沌纪元建议至少包含三至五轮不同主导因素的危机，而不是直接等待碰撞：

1. 热环境与食物压力；
2. 辐射与设施防护；
3. 大气和长期维生；
4. 跨区域物流与知识保存；
5. 终局工程的最后窗口。

危机强度来自实际模拟，策划只规定教学顺序、可接受范围和恢复窗口，不能伪造固定天象结果。

#### P2-3 难度改变信息和恢复条件

除稳定年数外，难度还可以调整：

- 初始观测噪声与记录完整度；
- 预测有效期和预警提前量；
- 设施耐受余量；
- 灾后恢复窗口；
- 初始人口结构与资源冗余。

难度不得直接让规则层真值泄露给文明，也不应仅通过提高数值消耗制造重复劳动。

## 7. 首个三十分钟纵向切片

首轮改造应先做一段可以独立证明核心循环的三十分钟体验：

### 0—5 分钟：建立生存基线

- 选定首都时游戏保持暂停；
- 候选区域显示文明当时能够知道的食物潜力、环境风险和不确定性；
- HUD 明确显示初始食物净变化和可维持天数；
- 玩家完成第一项实际生产岗位分配。

### 5—10 分钟：第一次主动观测

- 玩家在有限人员中选择生产、记录天空或制作简易仪器；
- 不同选择影响信息质量和眼前资源余量；
- 玩家获得第一条有不确定性的环境异常线索。

### 10—20 分钟：形成并比较预案

- 预测显示可能到来的寒潮或辐射窗口及置信区间；
- 玩家在增产食物、修建庇护、迁移人口、保存记录和改善观测之间取舍；
- 所有方案显示人员、材料、时间和被推迟项目。

### 20—30 分钟：危机结算与科学复盘

- 危机按真实环境状态抵达；
- 人口、生产、设施和知识按所在地与保护条件结算；
- 报告对比预测和实际，解释误差与损失；
- 新证据打开下一条研究或工程分支；
- 玩家选择恢复优先级，开始下一轮循环。

该纵向切片完成前，不扩充新的中后期科技时代。

## 8. 实施顺序与依赖

推荐按以下顺序实施：

1. 修正活动人口暴露、脱水保护和文明失败条件；
2. 建立可保存、可承诺、只结算一次的危险事件；
3. 打通一次危机后的损失报告和恢复选择；
4. 建立逐区域资源、运输、功率和储能结算；
5. 将主 HUD 改造成有趋势、来源和截止时间的驾驶舱；
6. 统一项目队列、事件流和暂停规则；
7. 增强研究实验、设施争用和科技实际消费方；
8. 用行政、通信和自动化科技逐步替代重复操作；
9. 完成一条聚变或轨道工程终局；
10. 在完整循环稳定后，再扩展年龄、水、维护、通信延迟和更多危机类型。

依赖规则：

- 没有真实伤害结算，不先增加更多避难建筑；
- 没有地方投入结算，不先增加更多生产资源；
- 没有科技消费方，不先增加科技节点；
- 没有项目列表与事件流，不继续增加同时运行的项目种类；
- 没有一个可完成的终局，不继续拉长稳定纪元。

## 9. 玩法验收指标

每个版本除解析和自动化测试外，还应记录以下体验指标：

1. **决策频率**：正常速度下，玩家是否能在合理间隔内遇到一次有机会成本的选择，而不是长期等待；
2. **因果解释率**：重大资源变化、伤亡和停工是否都能从界面追溯到来源；
3. **科技兑现时间**：主要科技完成后一到两个操作周期内，是否出现新信息、命令或工程；
4. **空间有效性**：更换建设地点、运输路径或庇护区域是否能改变可测量结果；
5. **危机分歧度**：同一真实危险下，不同预案是否产生明显且合理的差异；
6. **操作增长率**：文明人口和区域扩大后，必要点击数是否因组织与自动化能力而得到控制；
7. **信息边界**：低科技状态是否始终不能读取高精度预测或隐藏真值；
8. **终局可达性**：玩家是否能理解当前阶段目标、失败原因和通往终局的科技—工程链。

每个新增玩法功能必须有对应的自动化验证；涉及导航或交互的改动还要完成实际操作路径测试。只有界面显示而没有模拟效果，或只有后端状态而没有玩家可用入口，都不算完成。

## 10. 当前不应优先实施的方向

- 继续增加没有消费方的科技节点；
- 继续增加只提供线性产量倍率的政策；
- 以更多资源图标代替地方生产因果；
- 为制造紧张感而向玩家泄露精确灾害倒计时；
- 引入居民个体级需求、装备和手工控制；
- 用随机剧情事件代替真实模拟危机；
- 在核心循环闭合前优先进行大规模装饰性 UI 重制；
- 用战争、敌对外星单位或英雄系统转移经营深度问题。
