## 项目概述

《三体文明》是一款基于刘慈欣《三体》世界观的三维星际经营模拟游戏。玩家在乱纪元中建立文明，发展科技，应对三体世界的不稳定环境。

### 技术栈

- **引擎**: Godot 4.7
- **脚本语言**: 纯 GDScript
- **3D 渲染**: SubViewport + Camera3D + StandardMaterial3D（星图）；2D 热力图手绘（区域浏览）
- **UI 系统**: Control 节点 + Theme + `_draw()` 手绘列表/图表
- **存档**: JSON（FileAccess 读写 `user://` 路径）
- **物理**: Jolt Physics（星图交互预留）

> **历史**: 项目原为 Python/Pygame 实现（2026-04）。2026-07 完全重写迁移至 Godot 4。
> 迁移完成度：模拟核心 100%，场景骨架 100%，3D 渲染 / UI 交互 / 存档流程仍在施工中。

## 模拟子系统详解

### 1. 三体运动模拟 — `scripts/simulation/three_body.gd`

`class_name ThreeBodySimulation extends RefCounted`

**功能**: 4 天体（3 恒星 + 1 行星）引力模拟，输出环境参数供其他模块消费。

**关键常量**:
- `G = 1.0` — 简化引力常数
- `TRAIL_LENGTH = 200` — 每星轨迹点数

**内部类 StarData**: 持有 mass / position / velocity / color / radius / is_planet / trail

**关键方法**:

| 方法 | 功能 |
|---|---|
| `_init()` | 随机生成层级稳定初始配置（内双星 + 外第三星 + 行星绕双星） |
| `compute_forces_for_state(positions)` | 遍历星对计算引力合力（用于 RK4 四步） |
| `update(dt)` | RK4 四阶积分 + 1e-5 随机微扰 + 轨迹 pop_front |
| `get_environment_params()` | 输出光照强度（归一化）/ 热等级 / 温度 / 辐射 / 稳定性 |
| `get_stars_data()` | 返回 [{position, mass, is_planet}, ...]（供区域系统） |
| `get_planet_position()` | 返回行星坐标 |

**环境参数公式**:
- 光照强度 = `clamp(Σ mass×10/(dist²+100) / 8, 0, 1)`
- 温度 = `-273.15 + total_intensity × 7000`
- 辐射 = `Σ mass×200 / dist^2.5`
- 稳定性 = `1 / (1 + 行星加速度/0.1)`

### 2. 行星区域系统 — `scripts/simulation/planet_zones.gd`

`class_name PlanetZoneManager extends RefCounted`

**功能**: 72 区域（12 经度 × 6 纬度）的自转、光照、温度、辐射模拟。

**关键常量**:
- 6 种地形: 平原 / 高原 / 山地 / 峡谷 / 盆地 / 丘陵
- `TERRAIN_RESOURCE_TABLE` — 地形→矿物/肥沃/藻类系数
- `TERRAIN_THERMAL_MODIFIER` — 地形默认温度修正（高原-6°C / 山地-10°C / 盆地+3°C）

**内部类 PlanetZone**: 持有 zone_id / 地形 / 温度 / 辐射 / 光照 / 资源禀赋 / 建筑列表 / 面积权重

**关键方法**:

| 方法 | 功能 |
|---|---|
| `_init(env_config)` | 初始化 72 区 + 构建邻居缓存 |
| `_init_zones()` | 按经纬划分 72 格，随机分配地形和资源（±30% 浮动） |
| `_build_neighbor_cache()` | 每区 ≤4 邻居（经纬相邻，经度环绕） |
| `update(dt, time_scale, stars_data, planet_pos)` | 更新自转角度 → 逐区环境计算 |
| `initialize_temperatures(stars_data, planet_pos)` | 跳过惯性直接设定目标温度 + 10 轮扩散 |
| `_compute_zone_environments()` | 光照（法线 cos + 暗面散射）→ 温度（热惯性趋近）→ 辐射 + 扩散 |
| `_apply_diffusion(dt)` | 区域温度向邻居均值靠拢 |
| `get_average_environment()` | 加权平均（面积权重）返回全局温/辐/光 |
| `get_zone(zone_id)` | 按 ID 返回 PlanetZone |
| `get_all_zones_summary()` | 返回 72 区简要数据列表（2D 热力图渲染用） |
| `add_building_to_zone / remove_building_from_zone` | 维护区域-建筑关联 |
| `get_state() / load_state()` | 序列化 / 反序列化 |

**工作效率函数** (`_calc_work_efficiency`):
- -10°C ~ 40°C → 1.0（满分）
- < -80°C 或 > 100°C → 0.0（无法工作）
- 中间线性插值

### 3. 实体管理器 — `scripts/simulation/entity_manager.gd`

`class_name EntityManager extends RefCounted`

**功能**: 管理 7 种资源、所有建筑、人口增长/库存/食物消耗。

**三种内部类**:
- `GameResource` — 单种资源（name / amount / max_storage / add / consume）
- `PopulationManager` — 人口系统（total / breeders / stored_population / 增长 / 饥荒 / 库存操作）
- `GameBuilding` — 单个建筑（17 种类型，耐久 / 产出 / 消耗 / 建造进度 / 环境伤害）

**7 种资源**: 铁矿 / 铜矿 / 稀有矿物 / 藻类燃料 / 化石燃料 / 电力 / 食物

**关键方法**:

| 方法 | 功能 |
|---|---|
| `_init(config)` | 初始化资源池和人口（100 人起始） |
| `add_building(building)` | 添加建筑到列表 |
| `get_resource(name)` | 查资源量，"population" 转发到 PopulationManager |
| `consume_resource / produce_resource` | 资源存取 |
| `get_buildings_by_type(type)` | 筛选活跃同类型建筑（科研产出用） |
| `get_idle_population()` | 总人口 - 生育者 - 建筑工人 |
| `assign_worker_to_building / unassign_worker_from_building` | 工人分配 |
| `assign_breeders / unassign_breeders` | 生育分配 |
| `get_electricity_balance()` | 发电量 vs 耗电量 |
| `update(env_params, zone_manager, dt, dehydrated)` | 重算库存容量 → 环境伤害 → 建造进度 → 产出消耗 → 人口增长 |
| `_process_buildings(dt, zone_manager, dehydrated)` | 电力比惩罚 + 区域效率 + 脱水惩罚 → 产出注入 |
| `get_state() / load_state()` | 全量序列化（含所有建筑详情） |

**建筑产出公式**: `workers × per_worker × durability_ratio × automation × zone_eff × power_ratio`

**人口增长公式**: `breeders × base_growth_per_breeder × food_satisfaction + idle × natural_growth_rate × food_satisfaction`

### 4. 科技树 — `scripts/simulation/tech_tree.gd`

`class_name TechTree extends RefCounted`

**功能**: 5 层 17 节点科技树，3 种科研点数（基础/应用/理论），渐进式注入研究。

**内部类 TechNode**: 持有 id / name / tier / column / research_cost / resource_cost / prerequisites / unlocked / researching

**17 个科技节点**:

| Tier | 节点 | 科研点需求 |
|---|---|---|
| 0 | telescope（望远镜） | 基础 80 |
| 0 | survival_shelter（维生庇护所） | 基础 60 |
| 0 | basic_metallurgy（基础冶金） | 基础 100 |
| 0 | basic_agriculture（基础农业） | 基础 50 |
| 1 | computer（计算机技术） | 基础 200 + 应用 50 |
| 1 | observatory（天文观测站） | 基础 150 |
| 1 | deep_shelter（深地庇护所） | 基础 120 + 应用 30 |
| 1 | laboratory（实验室） | 基础 180 |
| 1 | basic_electrification（基础电气化） | 基础 100 |
| 1 | fossil_fuel_extraction（化石燃料开采） | 基础 120 |
| 2 | power_plant（火力发电站） | 应用 140 |
| 2 | chaos_prediction（混沌预测模型） | 应用 200 + 理论 50 |
| 2 | automation（自动化控制） | 应用 150 |
| 2 | radiation_armor（防辐射装甲） | 应用 100 + 基础 80 |
| 2 | applied_physics（应用物理） | 应用 200 |
| 2 | material_science（材料科学） | 应用 180 |
| 3 | academy（科学院） | 应用 300 + 理论 100 |
| 3 | high_alloy（高强度合金） | 应用 250 |
| 4 | nuclear_fusion（可控核聚变） | 理论 500 + 应用 300 |

**关键方法**:

| 方法 | 功能 |
|---|---|
| `_init(config)` | 从 config["technology"] 构建节点（无 config 时用硬编码默认） |
| `produce_research(type, amount)` | 产出科技点 → 优先注入当前研究 → 剩余入池 → 检查完成 |
| `start_research(id, entities)` | 扣物质资源 → 标记 researching → 清空 progress |
| `cancel_research()` | 退回已注入点数（物质不退还） |
| `can_start_research(id, entities)` | 检查前置科技/资源/人口/单研究限制 |
| `get_research_progress()` | 当前研究整体进度百分比 + 各类型明细 |
| `is_researchable(id)` | 前置已解锁且自身未解锁未研究中 |
| `get_state() / load_state()` | 解锁列表 + 研究进度 + 科技点数池 |

**科研产出来源**（在 GameState._process_research_output 中）:
- 人口自然产出 = `population / 500 × 天数`
- 研究院（research_institute）→ 基础科研 1.0/工人/天
- 实验室（laboratory）→ 应用科研 2.0/工人/天
- 科学院（academy）→ 理论科研 1.0/工人/天
- 脱水状态 × 0.1

**关键方法**:

| 方法 | 功能 |
|---|---|

| `get_construction_decisions()` | 返回所有建造类决策 |
| `get_policy_decisions()` | 返回脱水/浸泡两个政策 |

## 场景脚本功能说明

### scenes/main.gd
入口场景，`_ready()` 中 `call_deferred` 跳转到 `initial_menu.tscn`。

### scenes/main_menu/initial_menu.gd
标题画面。3 个按钮 → StartGameMenu / SettingsScreen / quit()。使用 `$MainVBox/ButtonName` 路径引用节点。

### scenes/main_menu/start_game_menu.gd
最复杂的菜单场景。4 种 State（MAIN / NAMING / LOAD_UNIVERSE / LOAD_SAVE）：
- **MAIN**: 新游戏 / 继续游戏（找最新存档） / 加载存档 / 返回
- **NAMING**: LineEdit 输入宇宙名 → 调用 `GameState.new_game(name)` → 跳转 MainScreen
- **LOAD_UNIVERSE / LOAD_SAVE**: 手绘列表（`_draw()`）+ 滚轮滚动 + 点击选择 + 删除确认覆盖层
- 按住键盘 Enter / Delete / Escape 支持快捷键

### scenes/main_menu/settings_screen.gd
4 个标签页（游戏/显示/音频/控制），通过代码动态构建 `HSlider` + `CheckBox` 控件。`_load_settings()` 从 `user://settings.json` 读取，`_save_settings()` 写入并应用全屏/vsync。设置数据作为脚本成员变量（非持久化到 GameState）。

### scenes/game/main_screen.gd
游戏主界面，最关键的 UI 脚本：
- `_ready()`: 若 `GameState.game_started == false` 则创建默认宇宙；启动 60Hz Timer
- `_on_simulation_tick()`: 调用 `GameState.update(0.016)`
- `_refresh_panels()`: 响应 `GameState.state_updated` 信号 → 重建资源面板（按组分）/ 文明面板（人口+科研）/ 环境面板（温度+辐射+光照+天数+时间倍率）
- 工具栏: 暂停 / 1x/2x/3x/5x 调速 / 科技树 / 政策 / 区域 / 星图 按钮

### scenes/game/game_menu.gd
暂停菜单。5 个按钮通过 `%UniqueName` 绑定 → 继续 / 保存 / 加载 / 设置 / 主菜单。

### scenes/starmap/starmap_view.gd
3D 星图可视化：
- 运行时动态生成 `SphereMesh` + `MeshInstance3D`（每星一个，从 `GameState.get_state()` 取位置/颜色/半径）
- 30fps Timer → 更新星体位置 + 摄像机
- 摄像机: 球坐标旋转（`_cam_angle_h`, `_cam_angle_v`, `_cam_distance`）
- 鼠标拖拽旋转 / 滚轮缩放 / 行星锁定模式
- `_input()` 处理 MOUSE_BUTTON_LEFT / WHEEL_UP / WHEEL_DOWN / MOUSE_MOTION

### scenes/tech_tree/tech_tree.gd
科技树 2D 可视化：
- `_draw()` 手绘节点矩形 + 科技名 + 层级标签
- 4 种颜色: 绿（已解锁）/ 黄（研究中）/ 蓝（可研发）/ 灰（锁定）
- 前置连线: `draw_line()` 连接每节点到其前置节点
- 顶部显示三种科技点数余额 + 当前研究进度

### scenes/zone_view/zone_view.gd
2D 区域热力图：
- 左面板: 12×6 网格，按温度/辐射/光照三种模式着色
- 右面板: 选中区域详情（地形/温度/辐射/光照/建筑数/工作效率）
- 三种模式按钮切换 `view_mode`

### scenes/decision/decision.gd
政策与建造界面：
- 上半: 文明状态标签（正常/脱水 + 库存人口）
- 动态生成建造按钮列表（从 `dm.get_construction_decisions()`）
- 动态生成政策按钮（脱水/浸泡）
- 点击调用 `dm.execute_decision()`（建造默认 zone_id=0，后续 Phase 4 接入区域选择）
